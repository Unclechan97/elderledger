# 02 需求设计（PRD）

> 版本 v0.1 · 2026-09-11 · 本地开发为基准（微信开发者工具 + 局域网真机）

## 1. 产品定位

**银龄记账**：给 60 岁以上、以微信为主要沟通工具的老年人用的"开口就能记"的记账小程序。

- 核心价值：不打字、不看小字、不记流程 —— 说一句或拍一张，账就记好，还会读给你听。
- 协同价值：子女可远程查看（P1 绑定），帮忙把关、代记。
- 边界：不做复式记账、不做投资理财、不做预算体系（只做"本月花了多少"级别的口语化汇总）。

## 2. 用户画像

| 画像 | 特征 | 核心诉求 |
|------|------|----------|
| 王阿姨 · 68 · 主管家庭日常开销 | 微信只用来聊天+支付，不会拼音打字；现金与微信支付各半；高频场景是买菜 | "记不清这个月花了多少"；记账 App 太复杂学不会 |
| 李大爷 · 72 · 慢性病常买药 | 会接视频不会打字；关心每月药费 | 想知道"这月药花了多少"，说给手机听就行 |
| 小芳 · 40 · 女儿（协同角色） | 不与父母同住 | 远程看爸妈的账，异常大额能发现；能帮忙补记 |

## 3. 适老化设计原则（8 条）

依据：工信部《移动互联网应用(App)适老化通用设计规范》（2021）、GB/T 37668-2019。

1. **大字高对比**：核心正文 ≥ 36rpx，金额/汇总数字 ≥ 72rpx；深色文字浅色底，对比度 ≥ 4.5:1；提供全局字号调节（标准/大/特大）。
2. **触控目标 ≥ 88rpx**（约 44px），按钮间距充分，单手可及；禁用双击/长按等隐手势作为唯一路径。
3. **一屏一事，层级 ≤ 2**：首页即记账；严禁广告、弹窗、诱导分享。
4. **语音优先，全程可说**：每个记账入口都能用语音完成；每步操作有 TTS 语音反馈。
5. **记一笔 ≤ 3 步**；说不清/识别错永远有手动兜底入口。
6. **防误触**：写入前必须经"大卡片确认"；删除需二次确认且默认不可恢复前有播报提示。
7. **分类 ≤ 8 个支出类 + 3 个收入类**，图标 + 颜色 + 名称三重编码，帮助识字量低的用户。
8. **免注册轻启动**：静默获取 openid，无注册/登录表单；首次进入 1 页引导（大图 + 语音讲解）。

## 4. 功能需求

### P0（MVP，M1–M4 交付）

| 编号 | 功能 | 说明 |
|------|------|------|
| F1.1 | 🎤 语音记账 | 按住说话 → 本地 ASR 转文字（FunASR，Docker）→ GLM-4-Flash 解析出 金额/收支/分类/日期/备注 → 确认卡片 → 保存并 TTS 播报"记好了，今天买菜十五元" |

## 5. 核心流程

### 5.1 语音记账（主流程）

```
首页点 [🎤 说一笔]
   → 按住大按钮说话（最长 30s，松手即结束）
   → 本地 ASR 得到文本（界面上同步大字显示识别文本）
   → 上传 /api/parse/text → GLM-4-Flash 解析
   → 确认卡片（金额/分类/日期 大字） + TTS："买菜十五元，对吗？"
        ├─ 点 [✅ 记好了] → 保存 → TTS："记好了" → 回首页
        ├─ 点卡片字段 → 修改 → 再确认
        └─ 点 [🔁 重说] → 回到按住说话
   失败兜底：ASR 为空 / 解析置信度 < 0.7 → 自动进手动页（能填的都预填）
```

### 5.2 拍照记账

```
首页点 [📷 拍一张] → 拍摄/选择小票或支付截图
   → 本地压缩（≤ 5MB）→ 上传 /api/parse/image → GLM-4V-Flash 提取
   → 确认卡片（同上）
   失败兜底：图片过大 / 识别失败 → 提示"没看清，请手动记" → 预填手动页
```

### 5.3 手动记账

```
首页点 [✋ 手动记] → 金额大键盘 → 分类九宫格 → [记好了]（日期默认今天）
```

## 6. 老年口语语义规则（LLM 解析约定）

| 用户说 | 解析为 |
|--------|--------|
| "买菜花了十五块" | 支出 ¥15.00 · 吃饭买菜 · 今天 |
| "早上买药一百二" | 支出 ¥120.00 · 医疗药品 · 今天 |
| "给孙子红包两百" | 支出 ¥200.00 · 人情往来 |
| "女儿给我两千块" | 收入 ¥2000.00 · 子女给 |
| "水电费三十八块五" | 支出 ¥38.50 · 水电日用 |
| "昨天打车二十" | 支出 ¥20.00 · 交通出行 · 昨天 |
| 口语换算 | 块=元、毛=角、"两百"=200、"十五块"=15 |
| 说不清（"花了一点钱"） | amount=null, confidence 低 → 进手动页 |

## 7. 非功能需求

| 维度 | 要求 |
|------|------|
| 性能 | 语音：松手后 ≤ 2s 出确认卡片（ASR 本地+解析）；拍照：≤ 4s；超时明确提示并可重试 |
| 可靠性 | 每次语音/照片解析留存原始输入与 LLM 输出（parse_log 表），识别错误可追溯、可优化 |
| 隐私 | 照片仅用于识别，识别完成后默认删除原图（设置可改）；本地开发阶段数据不出本机（GLM API 除外） |
| 无障碍 | 满足工信部适老化规范精神：无广告弹窗、字号可调、语音辅助、验证/确认简单直接 |
| 兼容 | 微信基础库 ≥ 2.30；iOS/Android 主流机型真机验证；开发者工具仅用于开发，体验以真机为准 |

## 8. 验收标准（示例）

| 用例 | 步骤 | 通过标准 |
|------|------|----------|
| 语音-普通话 | 说"买菜花了十五块" | 卡片显示 支出 ¥15.00 吃饭买菜 今天；确认后明细出现该条且汇总+15 |
| 语音-口语金额 | 说"给孙子红包两百" | 人情往来 ¥200.00 |
| 语音-兜底 | 说"花了一点钱" | 进入手动页且不崩溃，无金额预填 |
| 拍照-支付截图 | 上传微信支付截图 | 卡片金额与截图一致（±0），商户进备注 |
| 拍照-模糊图 | 上传拍糊的小票 | 提示没看清并进入手动页 |
| 手动-大键盘 | 完整记一笔 38.5 | 金额显示 38.50，无浮点尾差 |
| 防误触 | 在明细左滑删除 | 弹大字确认框，取消则不删 |
| 适老化走查 | 对照设计原则 8 条逐页检查 | 全部页面无 < 36rpx 核心文本、无广告、无二级以上弹窗嵌套 |
