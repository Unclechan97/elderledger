# 05 开发计划

> 版本 v0.1 · 2026-09-11 起步 · 本地开发为基准

## 里程碑

### M0 · 脚手架（1 天）
- 仓库结构（miniprogram/ + server/）；小程序 TS 模板跑通开发者工具
- **Docker Compose 三容器**：app（Express 5 + better-sqlite3）/ asr（FunASR runtime）/ tts（edge-tts）；schema 建表 + 分类 seed
- /api/categories 与 /api/asr 冒烟：录一段测试 wav，FunASR 容器转写成功
- 开发者工具「不校验合法域名」+ 局域网代理配置；.env 接入智谱 Key
- **验收**：模拟器首页请求到预置分类 JSON；`docker compose ps` 三容器健康；测试 wav 转写出正确文本
- **执行记录（2026-09-11）**：脚手架完成并提交（00f0da1）。机器 14GB 内存、空闲仅 0.9GB，**按用户决定 asr 冒烟挪至 M2 开工 spike**（M0 验收缩减为分类 + TTS 两项）；asr 启动前需先腾内存（关大程序或 WSL 限内存重启）。测试语音用 Windows SAPI（Huihui 音色）本地生成，不依赖外网。

### M1 · 手动记账闭环（2 天）
- 手动记账页：大键盘 + 分类九宫格 + 日期选择
- 确认卡片组件（三种输入共用的核心组件）
- 明细列表 + 删除二次确认；首页汇总（/api/summary）
- **验收**：模拟器+真机各手动记 10 笔，汇总与明细准确，金额无浮点尾差
- **执行记录（2026-09-12）**：代码完成并提交（9d64a5f）。服务端记账/明细/汇总三接口 curl 冒烟通过（含 400 校验与删除回滚）；前端 tsc 严格模式零错误。待模拟器/真机人工验收 10 笔。

### M2 · 语音记账（2.5 天）
- RecorderManager 录音（wav 16k 单声道）+ /api/asr（转发 FunASR 容器）；voice-button 组件（按住说话、识别文本大字实时显示）
- /api/parse/text：正则兜底层 + GLM-4-Flash（json_schema）
- /api/tts（edge-tts + 短语缓存）+ TTS 播报（确认前播"对吗"，保存后播"记好了"）；置信度兜底流
- **执行记录（2026-09-12）**：代码完成并提交（aef77f5）。**asr 容器冒烟通过**（机器空闲内存恢复到 2.7GB 后启动成功；两个坑：run_server.sh 须 cd 进脚本目录执行、offline 模式结果帧 is_final 恒 false 靠宽限定时收尾）；/api/asr 全链路 2 秒识别"今天买菜花了，15 块。"；正则解析层 8/8（覆盖"块五/交了三百/五毛八/给我一百二"等口语省略）；TTS GET 通道 8KB mp3。待真机验收（麦克风权限、真实老人口音）。
- **补充（2026-09-12，用户要求识别可切换）**：ASR 改 provider 可配置——`ASR_PROVIDER` 环境变量
  （默认 funasr），接缝 = `transcribeAudio(Buffer, mime) → 文本`（services/asr/index.ts 分发 switch，
  funasr.ts 是第一个实现）。将来接云 API（讯飞/百度/阿里）或 sherpa-onnx 兜底：加 <provider>.ts +
  switch 一个分支，/api/asr 与前端契约 {text} 不变。已实测 funasr 链路不受影响。
  另两段本就可配置：解析层 LLM_PROVIDER（zhipu，预留 ollama）；TTS 换引擎 = 换 TTS_URL（协议不变）。
- **验收**：需求文档 §8 语音用例全部通过；LLM 挂掉时正则层仍可记简单金额；真机从松手到出卡片 ≤ 3s（局域网）

### M3 · 拍照记账（2 天）
- chooseMedia + 压缩上传；/api/parse/image（GLM-4V-Flash）
- 支付截图与小票两类样张各 20 张实测，调 prompt
- 失败/低置信度 → 预填手动页
- **验收**：支付截图金额提取准确率 ≥ 85%（40 张样张）；模糊图正确走兜底
- **执行记录（2026-09-12）**：代码完成。用户配置 ZHIPU_API_KEY 后 LLM 文本层同步激活（"上个礼拜日儿子给我一千块钱"→ parser=llm，conf 0.95；其间修掉 llm.ts 引用 config 大写字段名导致 LLM 层从未启用的 bug，server 端 tsc 检查补入流程）。/api/parse/image（GLM-4V-Flash）System.Drawing 生成支付截图样张一次通过（¥15.50→1550 分→吃饭买菜），无金额灰图正确走兜底。前端拍照页（拍照/相册两大按钮 → 识别中 → 结果确认 + TTS 播报）。**待验收**：真实微信/支付宝截图与小票照片各 20 张实测准确率。

### M4 · 适老化打磨（1.5 天）
- 对照需求文档"设计原则 8 条"逐页走查（字号/触控/对比度/防误触）
- 全局字号调节（标准/大/特大）；TTS 全程覆盖；空态与错误态大字文案
- **待定功能（凭实测数据触发）——一次记多笔**：不做批量编辑 UI（确认成本 ∝ 笔数，违背低负担第一性）。
  改在解析层：LLM 返回数组 + 逐条卡片确认（语音"买菜十五打车十块"与账单列表截图共用该结构）。
  **触发条件**：M4 实测中"一次说多笔"高频出现（≥3 次/人/天）才做
- **执行记录（2026-09-12）**：两轮用户优化提案落地（97e4d94 + aed8ba1）。
  第一轮：#3 连续记账上线（三页保存后不退出，success-banner 带"本月已花"正反馈，尾部"完成，回首页"）；
  #1 多笔→等 M4 实测数据；#2 分类自定义→不做进老人端（见 M5 家人端代管）。
  第二轮：收入"生意进账"🏪 预置分类（幂等补种，一行数据解决，标签系统不做）；
  播报开关→首页导航行第 4 格直接切换（不做设置页）。
  **重要架构修正**：解析层改为正则优先/LLM 兜底——key 激活后实测 LLM 偶发金额换算错误
  （"五毛八"→5.8元、"三十块"→300元），正则是确定性计算；金额准确性 > 日期精度。冒烟 12/12。
- **执行记录（2026-09-12）**：适老化走查两轮完成（dde14f2 + 3f3c702）。8 条设计原则逐条对照：
  ①大字高对比达标（正文≥36/金额 88-96rpx；**"全局字号调节"降级为实测后按需**——给不识设置
  的用户加设置页是伪需求，微信系做法是默认就大，等 3 位老人实测反馈再定）；②触控主操作≥88、
  次级≥72rpx 达标；③一屏一事达标；④TTS 覆盖记账全链路（manual 确认卡片补上播报）；
  ⑤三链路均 ≤3 步且有手动兜底；⑥防误触补齐（删除前播报"删了就找不回来了"、语音 <1s 短录音
  拦截、manual 保存失败改大弹窗）；⑦分类 8+4（生意进账为用户明确需求，合理超出 8+3）；
  ⑧免注册 ✓ + 首次引导层补齐（三行大图标 + TTS 讲解，只出一次）。
  **M4 剩余验收需真人**：3 位 60+ 独立完成"语音记 3 笔 + 查本月花费"，无协助成功率 ≥80%。
- **真机调试进度（2026-09-12 暂停）**：电脑侧已全通——WLAN IP 192.168.1.101 ✓、端口 0.0.0.0:3000 监听 ✓、
  防火墙入站规则"ElderLedger 3000"已加 ✓、本机走局域网 IP 取 /health 成功 ✓、BASE_URL 已改 192.168.1.101。
  **卡在手机浏览器打不开 /health**——待排查（手机侧：浏览器自动 https/蜂窝数据未关/VPN；
  路由器侧：AP 隔离或访客网络）。下次继续按此清单排查；真机微信端还须开"开发调试"+麦克风授权。

### M5 · 家人协同 + 导出（P1，2 天）
- 邀请码绑定；家人只读汇总/明细；代记标记 source=family
- CSV 按月导出（格式对齐 ezbookkeeping 微信/支付宝导入格式）
- **分类管理放家人端**：老人端不做自定义分类（管理表单认知负荷最高 + 删除是破坏性操作 +
  个性化分类名会拉低语音/拍照解析命中率）。家人代管分类，老人端只读。
  **触发指标**：M4 实测"其他支出"占比 >20% 才值得做
- **验收**：两台手机绑定后，子女端看到与老人端一致数据
- **执行记录（2026-09-12）**：代码完成，服务端冒烟 14/14（邀请→绑定→me→elders→代记→只读拒绝→老人可删→越权回落→CSV→参数校验）。
  后端：`X-User-Id`/`X-View-As` 请求头模拟身份（上线换 code2Session，接口形状不变）；
  transactions/summary 全按 user_id 隔离；家人只读——DELETE 只认自己账本（修掉一个实现中途引入的漏洞：
  resolveViewUserId 对已绑定家人返回老人 id，原写法会让家人删掉老人记录）。
  family 路由 4 个（me/invite/bind/elders），邀请码 6 位去易混字符（0/O/1/I/L）；
  `/api/export/csv` 按月导出（UTF-8 BOM+CRLF，Excel 直接开；坑：fetch 的 text() 会剥开头 BOM，
  验证必须看原始字节）。
  前端：identity 工具 + 所有请求（request/uploadFile/downloadFile）注入身份头；
  家人页三态（老人出示邀请码超大字 → 绑定 → 家人管理视图）；
  **view-as 作用域收紧**：只在"看明细/代记/导出"动作期间临时设置，list/manual onUnload 即清、
  导出在 complete 回调清——否则家人回首页自己记一笔会写进老人账本（持久化 view-as 的初版有此漏洞）。
  list 代看横幅+隐藏删除；manual 代记横幅+source=family。
  本机调试入口：老人视图底部"我是子女？绑定"、家人视图底部"切回老人身份"（上线后身份来自 openid，删除）。
- **待验收**：两台手机绑定后子女端与老人端数据一致（依赖真机调试恢复；本地已用请求头链路等价验证）
- **补充（同日，用户指出导航占位未兑现）**：统计页上线（pages/stats）。适老化取舍：只做"钱花在哪儿"——
  本月支出大字 + 环比 + 分类排行（icon + 横向比例条 + 金额/笔数）；不做折线/饼图/月份切换
  （图表是认知负荷不是信息增益，月份切换等实测需求）。
  **同日追加（用户要求收入也要统计）**：统计页改两段式——"钱花在哪儿" + "钱从哪儿来"（收入分类排行，
  一屏滚动看全，比 tab 切换零学习成本；空段隐藏，整页全空才出空态）。/api/summary 改为对称返回
  by_expense_category + by_income_category（by_category 仅有 stats 一个消费者，直接改名）。
