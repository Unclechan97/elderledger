# 03 技术选型

> 版本 v0.1 · 2026-09-11 · 前提：本地开发为基准，全链路零成本优先

## 0. 选型总览（最终结论）

| 层 | 选型 | 一句话理由 |
|----|------|-----------|
| 小程序端 | 微信原生小程序 + TypeScript | 无跨端需求、调试链路最短 |
| 录音 | RecorderManager（小程序原生 API） | 无需插件，wav 16k 单声道直出 |
| 语音识别 ASR | FunASR Paraformer（本地 Docker，CPU） | 免费、离线、中文准确率第一梯队 |
| 语音合成 TTS | edge-tts（本地 Docker 内运行） | 免费、无密钥、音色自然 |
| 文本语义解析 | GLM-4-Flash（json_schema 结构化输出） | 免费不限量、口语金额/日期/分类解析 |
| 图片识别 | GLM-4V-Flash（免费多模态） | 免费且比模板 OCR 更适配"支付截图" |
| 后端 | Node.js 20 + Express 5 + TypeScript（Docker） | 轻、快、与前端同语言 |
| 数据库 | SQLite（better-sqlite3，WAL，卷挂载） | 零部署零运维，单文件易备份 |
| 部署 | Docker Compose（app / asr / tts 三容器） | 全部服务本地 Docker 化，一条命令起停 |
| 开发调试 | 微信开发者工具 + 局域网真机预览 | 关闭域名校验，手机与电脑同 WiFi 即可 |

## 1. 小程序端：原生 vs Taro vs uni-app

| 维度 | 原生 | Taro | uni-app |
|------|------|------|---------|
| WechatSI 等插件兼容 | ★★★ 官方直连 | 需插件类型声明，偶有坑 | 可用但多一层封装 |
| 适老化自绘组件 | 直接写 | 需经 React 转译 | 需经 Vue 转译 |
| 包体积/启动 | 最小 | 略大 | 略大 |
| 调试 | 开发者工具直调 | 多一层编译 | 多一层编译 |
| 未来跨 App/H5 | 不支持 | 支持 | 支持 |

**结论：原生 + TypeScript。** 本项目无跨端需求，适老化 UI 本来就要大量自绘组件，原生链路最短、坑最少。跨端诉求记录为已知取舍：若未来要 App 端，届时评估 Taro 重写或仅做 H5 版。

UI 组件策略：**不引入 Vant/WeUI 大组件库**，只自绘 4 个核心组件（确认卡片、大键盘、分类九宫格、语音按钮）——适老化的字号与触控规范无法靠通用组件库达成。

## 2. 语音输入选型

### 2.1 为什么放弃 WechatSI 插件（2026-09-11 实测结论）

小程序后台添加「微信同声传译」插件被拒，报错原文：

> 小程序使用的插件，其插件类目不能超过小程序主体类型当前开放的范围。
> 「微信同声传译」插件的类目是：IT科技 > 软件服务提供商，个人主体没有这个类目，不支持添加。

**个人主体被该插件的类目要求挡死，且无法绕过**——换服务类目无效，个人主体根本没有"IT科技 > 软件服务提供商"这个类目。彻底放弃插件方案，切换本地方案。

### 2.2 新方案：原生录音 + 本地 Docker ASR/TTS

| 环节 | 方案 | 说明 |
|------|------|------|
| 录音 | `RecorderManager` | 小程序原生 API，无插件依赖；`{ format: 'wav', sampleRate: 16000, numberOfChannels: 1, duration: 30000 }` |
| 传输 | `wx.uploadFile` → 服务端 `/api/asr` | 局域网内延迟可忽略；10s wav 16k 单声道约 320KB |
| ASR | **FunASR 官方 runtime Docker**（Paraformer 离线版，CPU） | WebSocket :10095；CPU RTF ≈ 0.1~0.3，5s 音频约 0.5~1.5s 出结果；中文准确率第一梯队，支持热词 |
| TTS | **edge-tts** 容器（FastAPI 封装，:55001） | 免费、无密钥、微软音色自然；返回 mp3 由 `InnerAudioContext` 播放；常用短语结果缓存 |

### 2.3 ASR 备选（均在 Docker 内可替换）

| 方案 | 优势 | 定位 |
|------|------|------|
| FunASR SenseVoice-small | 多语种+方言（粤/川/沪）+ 情感标注，CPU 更快 | 普通话模型方言不达标时切换 |
| faster-whisper (int8) | 多语种通用 | 备选 |
| sherpa-onnx zipformer | 极轻量、可流式 | 低配机器备选 |

### 2.4 相对插件方案的取舍

- 代价：多一个 ASR 容器（内存约 2~3GB，模型首次加载慢，`restart: unless-stopped` 常驻）；录音文件多一次上传（局域网 < 100ms）；edge-tts 调用微软免费端点（无需账号密钥，但非纯离线）
- 收益：不受插件审核（最长 7 天）与类目政策影响；无 TTS 150 字限制；开发者工具/真机少一层插件不确定性；方言模型有升级空间
- 若要求**完全离线**：TTS 可换 sherpa-onnx melo-tts（纯本地，音质略降），LLM 可切 Ollama（见 §4）

## 3. 图片识别选型

| 方案 | 成本 | 适配度 |
|------|------|--------|
| A. 微信服务市场 OCR 插件 | 按次收费 | 小票模板可用，支付截图支持差 |
| B. 腾讯云票据 OCR | 1000 次/月免费 | 票据强，但"支付截图"非标准票据，字段提取弱 |
| **C. 多模态 LLM：GLM-4V-Flash** | **完全免费**（单图 ≤ 5MB） | 小票+支付截图通吃，prompt 直接约定输出 JSON（金额/商户/日期/分类/置信度） |

**结论：C。** 老年人最高频的拍照对象是**微信/支付宝支付截图**（不是标准票据），模板类 OCR 覆盖差；多模态 LLM 天然处理非结构化版面，且与文本解析共用同一套智谱 API Key，运维成本最低。备选 B 留作图片量大/免费额度变化时的降级。

工程细节：`wx.chooseMedia` 用 compressed + `wx.compressImage` 控制在 5MB 内；识别后默认删除原图（隐私要求）。

## 4. 语义解析（语音文本 → 结构化记录）

- **GLM-4-Flash**：2024-08 起免费不限量；支持 `response_format: json_schema` 强制结构化输出；128K 上下文；约 72 tokens/s，延迟可接受。
- **正则兜底层**：服务端先跑一层轻规则（"数字+块/元"、日期词"昨天/早上"、分类关键词），规则命中且无歧义则不调 LLM —— LLM 挂了核心记账仍可用，且省延迟。
- 每次解析输出 `confidence`（0~1），< 0.7 前端自动转"预填手动页"。
- 用户已有智谱 open.bigmodel.cn 的使用基础（现有 API 体系一致），Key 管理与调用经验可直接复用。
- **可选全离线**：`LLM_PROVIDER=ollama` 时解析走 Docker 内 Ollama（qwen2.5:7b-instruct 等），整个语音链路不依赖外网；默认 `zhipu`（免费且解析质量更好）。

## 5. 后端选型

| 候选 | 优点 | 缺点 | 结论 |
|------|------|------|------|
| **Express 5 + TS** | 极轻、中间件生态成熟、上手 10 分钟 | 大项目结构松散（本项目规模不会到大项目） | ✅ 选用 |
| NestJS | 结构化、依赖注入 | 起步重、样板代码多 | 杀鸡用牛刀 |
| Python FastAPI | 若未来自托管 ASR（Python 生态）更顺 | 当前无此需求；两语言并存的维护成本 | 不选，预留切换理由记录在案 |

**数据库：SQLite（better-sqlite3）** —— 同步 API 简单可靠、WAL 模式并发够用、单文件备份 = 拷贝文件。DAO 层隔离 SQL，未来换 MySQL 只动一层。
**不选微信云开发**：绑定微信生态、调试黑盒、本地开发体验差，与"本地为基准"矛盾。

**鉴权**：`wx.login` → `code2Session` 拿 openid 静默建用户；本地阶段不做手机号/密码体系；P1 家人绑定用"老人端生成 6 位邀请码 + 子女端输入"方案。

## 6. 本地部署：全服务 Docker 化（用户约束）

```yaml
# docker-compose.yml（M0 落地，镜像 tag 以 FunASR 官方文档为准）
services:
  app:   # Express 5 + TypeScript + SQLite
    build: ./server
    ports: ["3000:3000"]
    volumes: ["./server/data:/app/data"]      # elderledger.db 卷挂载
    env_file: ./server/.env                   # ZHIPU_API_KEY / LLM_PROVIDER
    restart: unless-stopped
  asr:   # FunASR runtime（Paraformer 离线版，CPU）
    image: registry.cn-hangzhou.aliyuncs.com/funasr_repo/funasr:funasr-runtime-sdk-offline-cpu-<tag>
    ports: ["10095:10095"]                    # WebSocket
    volumes: ["asr-models:/workspace/models"] # 模型缓存，避免重复下载
    restart: unless-stopped
  tts:   # edge-tts FastAPI 封装
    build: ./server/tts
    ports: ["55001:55001"]
    restart: unless-stopped
volumes:
  asr-models:
```

- 微信开发者工具跑在宿主机，请求 `http://<电脑局域网IP>:3000`，勾选「不校验合法域名」
- 手机真机与电脑同 WiFi → 直接访问宿主机映射端口（Docker Desktop 端口映射默认绑定 0.0.0.0）
- GLM API Key 放 `server/.env`（已 gitignore），绝不入库、绝不写进小程序端代码
- 上线期再评估：微信云托管（免运维免备案）或轻量服务器——compose 文件可直接迁移

## 8. 技术风险与对策

| 风险 | 影响 | 对策 |
|------|------|------|
| ~~WechatSI 插件~~ | — | **已排除**：插件类目（IT科技>软件服务提供商）对个人主体不开放，无法添加（2026-09-11 实测） |
| ASR 容器内存占用高（约 2~3GB）、模型首载慢 | 本机资源 | compose 常驻 + 模型卷缓存；低配机器换 sherpa-onnx 轻量模型 |
| edge-tts 依赖微软免费端点 | TTS 不可用 | 常用短语结果缓存；可切 sherpa-onnx melo-tts 纯本地 |
| GLM-4V 识别错金额 | 记错账 | 确认卡片强制二次确认；parse_log 留存；置信度阈值兜底 |
| 免费 API 限流/政策变化 | 解析不可用 | 正则兜底层保证"能记上"；服务端可配置切换模型名 |
| 方言/口音 ASR 误识别 | 语音不可用 | 引导普通话 + 识别文本大字可见可改 + 手动兜底 |
| 小程序类目审核 | 无法上线 | 个人主体注册时确认"记账"所需类目（如 工具 > 效率/信息查询），登记为上线前待办 |
| 图片超 5MB | 上传失败 | 前端压缩 + 服务端再校验，明确提示重拍 |
